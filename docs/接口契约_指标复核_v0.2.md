# 接口契约：指标人工确认与修正 v0.2

日期：2026-11-26
状态：**实现基线**。取代 `接口契约草案_指标复核_v0.1.md`（v0.1 保留作历史，不再作为实现依据）。
范围：`POST /tasks/{task_id}/metric-reviews`，只处理**指标记录**的人工确认/修正；既有
`POST /tasks/{task_id}/review` 只处理检查项，两者不得混用。

本版依据《接口契约v0.1_前端确认与基线恢复》修订：采用现有字段 `manual`/`supersedes_id`，
补齐状态五态、空值语义、未知字段拒绝、幂等顺序、审计展示与失效规则。

---

## 1. 语义约束

| # | 约束 |
|---|---|
| 1 | `action=confirm` 只确认原记录，不新建记录、不改 `origin`/`status`；`action=correct` 新建人工修正记录并替代原记录。 |
| 2 | 必填 `record_id` / `expected_revision` / `reason` / `evidence_ids`；`correct` 额外必填 `correction`。 |
| 3 | 所有 Decimal 数值一律字符串（`"0.1300"`）；显式空值用 `null`，不能用 `""` 代替。 |
| 4 | `Idempotency-Key` 必填且为 UUID；作用域 = 用户身份 + 任务 + 操作 + 键，任务存续期持久。 |
| 5 | 成功返回新 `revision`、审计事件 ID、失效摘要；版本不符返回 409 且带当前 revision。 |
| 6 | 权限、任务/记录归属、证据关联全部服务端校验；客户端不得设置 actor/origin/review_state 等服务端字段。 |
| 7 | 原模型记录不覆盖：`correct` 以 `origin=manual` 的新记录 + `supersedes_id` 保留前后差异。 |
| 8 | 前端保存成功后按约定走 SSR 刷新；另提供受归属保护的只读审计 GET，非强制调用。 |

## 2. 请求

```
POST /tasks/{task_id}/metric-reviews
Content-Type: application/json
Idempotency-Key: <UUID>
X-User: <用户身份>       # 或同源 esg_user Cookie
```

Agent 令牌（Bearer / X-Agent-Token）一律 403。请求顶层**仅接受**下列字段，未知字段一律 400：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `action` | `"confirm" \| "correct"` | 是 | 非法值 400 |
| `record_id` | string | 是 | 必须为本任务当前有效记录；已失效记录 409 `INVALID_STATE` |
| `expected_revision` | integer | 是 | 布尔值、字符串、浮点数一律 400 |
| `reason` | string | 是 | 去空白后非空，最长 4000 |
| `evidence_ids` | string[] | 是 | 非空、去重；须属于该记录绑定报告与年度 |
| `correction` | object | `correct` 时是 | `confirm` 时不得出现 |

### 2.1 `correction` 可修改字段

`value`、`raw_value`、`raw_unit`、`canonical_unit`、`conversion_rule`、`denominator`、
`boundary_text`、`boundary_key`、`method_text`、`scope3_categories`、`extraction_note`、`status`。

- 不接受 `metric_id` / `report_id` / `task_id` / `metric_year` / `record_id` / `revision` /
  `review_state` / `is_current` / `origin` / `supersedes_id` / `derivation` / `actor`；出现即 400。
- **年份固定**：`metric_year` 不可修改，不允许借复核把记录移到另一年。
- **继承与清空**：省略字段 = 继承原值；显式 `null` = 清空，仅限 schema 允许为空的字段
  （`value` / `raw_value` / `raw_unit` / `canonical_unit` / `conversion_rule` / `denominator` / `boundary_key`）。
- 数值字段为字符串，须通过 JSON Schema 的 Decimal 模式；`metric_year` 不参与修正。

### 2.2 `status` 五态规则（不新增枚举）

| status | 要求 |
|---|---|
| `extracted` | `value` 为合法数值字符串；`raw_unit`、`canonical_unit` 非空；`evidence_ids` 非空且至少一条数值支持；`raw_value` 不得为 `/`、`—`、`未披露`、`未统计`。 |
| `missing_marker` | 保留 `/` 等原文标记于 `raw_value`（非空）；`value=null`；`evidence_ids` 非空且原文包含该标记。 |
| `unknown` / `conflict` / `parse_error` | `value=null`；`extraction_note` 非空说明依据；复核确认的是该状态及依据，**不表示数值已提取成功**。 |

历史 E02 `unknown` 修正为数值时必须同时给 `status="extracted"`，禁止留下“有值但 unknown”。

### 2.3 单位、分母、边界的一致性

- `raw_unit` 须通过现有 `UNIT_MARKERS` 指标口径校验；`canonical_unit` 用 `unit_identity()`
  做受控别名归一后比较，分母原样保留。
- 改变原值、单位或边界后，若原记录带 `conversion_rule` / `denominator`，请求必须**显式**
  提供这两个字段（可为 `null` 表示清空），否则 400：禁止数值已更新而换算说明仍描述旧值。
- `origin` 由服务端设置：确认时保持原值，修正时固定 `manual`；人工记录 `derivation=null`，
  历史派生公式留在原记录与审计中，不暗中放宽 schema。

### 2.4 归属与证据

- 记录须属于当前任务且为当前有效记录；跨任务或已被替代的记录拒绝。
- 证据须属于该记录绑定的 `report_id`；证据 `column_year` 非空时须等于 `metric_year`；
  仅属同一任务但属于另一份报告也拒绝。
- 证据还需实际支持内容：`extracted` 要求文本含该数值（数值等价，允许千分位/尾随零），
  `missing_marker` 要求文本含原文标记；其余状态要求文本归属与年度一致。

## 3. 成功响应（200）

统一信封 `ok/data/error/task_id/revision`；`error=null`。`data` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `action` | string | 回显本次动作 |
| `record` | object | 复核后的当前有效 MetricRecord |
| `audit_event_id` | string | 审计事件标识 |
| `invalidated.comparisons` | string[] | 标识数组：失效的比较 ID |
| `invalidated.checks` | string[] | 标识数组：失效的检查项 ID |
| `invalidated.score` | `"stale" \| "absent"` | 有评分并失效为 `stale`；原本无评分为 `absent` |
| `invalidated.exports` | string[] | 标识数组：失效的 artifact ID |

### 3.1 示例 A：数值修正（unknown → extracted）

请求：

```json
{
  "action": "correct",
  "record_id": "mr_E02_2024",
  "expected_revision": 10,
  "reason": "原记录为 unknown；按 p127 附录原表 0.1300 tCO2e/万元营收 补正，范围1+2。",
  "evidence_ids": ["ev_p127_E02_2024"],
  "correction": {
    "status": "extracted",
    "value": "0.1300",
    "raw_value": "0.1300",
    "raw_unit": "吨二氧化碳当量/万元营收",
    "canonical_unit": "tCO2e/万元营收",
    "denominator": {"kind": "revenue", "currency": "CNY", "scale": "1", "unit": "万元营收"},
    "conversion_rule": null,
    "boundary_text": "范围1+2，附录原表口径",
    "boundary_key": "scope1_2",
    "method_text": "附录原表披露值，未换算"
  }
}
```

响应（省略记录中与请求相同的字段）：

```json
{
  "ok": true,
  "task_id": "task_byd_2024",
  "revision": 11,
  "error": null,
  "data": {
    "action": "correct",
    "audit_event_id": "mrev_9f1c2da7b3e84a10",
    "record": {
      "record_id": "mr_corr_7c1d2f09a4b64813",
      "task_id": "task_byd_2024",
      "status": "extracted",
      "value": "0.1300",
      "raw_unit": "吨二氧化碳当量/万元营收",
      "canonical_unit": "tCO2e/万元营收",
      "origin": "manual",
      "supersedes_id": "mr_E02_2024",
      "derivation": null,
      "review_state": "confirmed",
      "revision": 11,
      "is_current": true,
      "evidence_ids": ["ev_p127_E02_2024"]
    },
    "invalidated": {
      "comparisons": ["cmp_E02_2023_2024"],
      "checks": ["C02", "Q02"],
      "score": "stale",
      "exports": ["art_a1", "art_b2", "art_c3"]
    }
  }
}
```

原记录 `mr_E02_2024` 保留且 `is_current=false`；审计事件含 before/after 快照。

### 3.2 示例 B：原文缺失标记修正（unknown → missing_marker）

请求：

```json
{
  "action": "correct",
  "record_id": "mr_E02_2023",
  "expected_revision": 11,
  "reason": "附录原表该单元为 /，按原文保留占位符，不推定 0。",
  "evidence_ids": ["ev_p127_E02_2023"],
  "correction": {
    "status": "missing_marker",
    "raw_value": "/",
    "value": null,
    "canonical_unit": null,
    "conversion_rule": null,
    "denominator": null,
    "extraction_note": "原表单元格为 /，无可用数值"
  }
}
```

响应要点：`record.status="missing_marker"`、`record.value=null`、
`record.origin="manual"`、`record.supersedes_id="mr_E02_2023"`、`revision=12`；
`invalidated` 结构同 3.1（无评分时为 `"score": "absent"`）。

### 3.3 示例 C：仅确认（不改数值/状态）

请求：

```json
{
  "action": "confirm",
  "record_id": "mr_E02_2024",
  "expected_revision": 12,
  "reason": "复核 p127 附录原表，单位分母与边界一致，确认现有记录。",
  "evidence_ids": ["ev_p127_E02_2024"]
}
```

响应要点：`record.review_state="confirmed"`、`record.origin` 与 `record.status` **保持原值**、
`record.record_id` 不变、无新记录；`revision=13`；审计与失效同上。
`confirm` 的顶层 `evidence_ids` 仅作为审计证据，不覆盖记录原有证据。

## 4. 错误响应

任何失败均为 `ok=false` / `data=null` / `error={code,message,retryable}` / `task_id` / `revision`；
版本冲突与幂等冲突带**当前** revision；401/403 的 `task_id`/`revision` 为 null（不泄露任务存在性）。
错误码沿用现有契约枚举，具体原因见 message：

| 状态 | code | message 标识 | 触发 |
|---|---|---|---|
| 401 | `UNAUTHORIZED` | `user session required` | 无用户会话 |
| 403 | `FORBIDDEN` | `agent token cannot review` | Agent 令牌 |
| 403 | `FORBIDDEN` | `task owner mismatch` | 任务归属用户不符 |
| 404 | `NOT_FOUND` | `task not found` / `record not found` | 任务或记录不存在/跨任务 |
| 409 | `INVALID_STATE` | `record superseded` | 旧记录被替代后再次提交 |
| 409 | `REVISION_CONFLICT` | `task changed` | 版本不符，带当前 revision |
| 409 | `IDEMPOTENCY_CONFLICT` | `Key was used for a different request` | 同键异体 |
| 400 | `INVALID_INPUT` | `invalid JSON` / `unknown field` / `invalid action` / `expected_revision` / `reason required` / `evidence_ids required` / `correction required` / `invalid correction` | 结构、类型、必填、未知字段、状态/单位/分母/证据支持失败 |
| 400 | `FOREIGN_EVIDENCE` | `evidence outside record scope` | 证据不属于该报告/年度 |
| 500 | `INTERNAL_ERROR` | `Business operation failed` | 未预期异常，事务已回滚 |

## 5. 幂等与事务

- 阶段顺序：鉴权与任务归属 → **查幂等成功结果** → 版本检查 → 业务校验与写入。
  超时/断连后用**同一键 + 完全相同请求体**重放，返回首次成功结果（含同一 revision 与事件 ID）；
  编辑草稿形成新操作时生成新键，不得给原请求换键盲重试。
- 同键异体 409；并发同键由 SQLite `BEGIN IMMEDIATE` + 唯一约束串行，只提交一次。
- 记录变更、审计、失效、revision 递增、幂等记录写入同一事务；任一失败整体回滚。
- 幂等记录任务存续期持久，重启后仍可重放；不做基于时间的过期。

## 6. 失效规则

| 动作 | comparisons | checks | score | exports |
|---|---|---|---|---|
| `confirm` | 引用该记录的比较失效 | 该指标关联的检查项置 `unknown`/`unreviewed`/`is_current=false` | 有则 `stale`，无则 `absent` | 当前产物 ID 全部失效 |
| `correct` | 引用原记录或新记录的比较失效 | 同 confirm | 同 confirm | 同 confirm |

失效项为标识数组，前端按 ID 刷新 SSR，不要求客户端猜测结构。

---

## 7. 审计展示（只读）

`GET /tasks/{task_id}/metric-reviews`：用户会话 + 归属保护，Agent 令牌 403；返回按 revision
倒序的事件列表，每条含 `audit_event_id` / `actor` / `action` / `record_id` /
`before` / `after` / `reason` / `evidence_ids` / `revision` / `at`。不提供写入或删除审计的接口。

- 任务归属不符返回 **403**、任务不存在返回 **404**，两者 `data=null` 且 `task_id`/`revision`
  均为 null（与统一信封「权限/存在性失败不泄露任务信息」一致）；无会话 401。
- 审计事件**完整保留、不按条数截断**，历史复核全程可追溯；超过 200 条时 GET 返回全部。

## 8. 测试矩阵（离线，额度 0）

- 无会话 401；Agent 令牌（含携带 Cookie）403；伪造 actor 字段 400。
- 跨任务记录/证据 404/400；同任务异报告证据 400；证据年份不符 400；数值无证据支持 400。
- 旧 revision 409 且带当前 revision；同键重放结果完全一致；同键异体 409；并发同键仅一次写入；
  不同键同版本并发只有一个成功、其余 409。
- 审计超过 200 条不截断；审计 GET 归属不符 403、任务不存在 404，均不返回 revision。
- 导出失效在事务提交后刷新：提交后刷新失败/重启/幂等重放均不改变已提交结果，旧导出按 revision 恒为过期。
- 缺理由、空证据、非法 action、布尔/字符串 revision、未知字段、非当前记录、状态矛盾均拒绝且无半写入。
- `confirm` 不新建记录、不改 origin/status；`correct` 原记录保留、新记录 `origin=manual`、
  `supersedes_id` 指向原记录、前后差异入审计。
- 数值修正与 `missing_marker` 修正各有一条完整请求/响应示例（第 3 节）。
- 失效：比较/检查/评分/导出均返回标识；事务注入失败后 revision、记录、审计、幂等表无残留。

## 9. 剩余问题（不阻塞实现）

1. 任务归属目前以任务元数据中的 `owner`/`user_id`（若存在）为准；未标注的本地原型任务对所有
   已登录用户开放。若需真正的多用户任务授权，需要单独的授权模型变更。
2. `GET /tasks/{task_id}/metric-reviews` 已实现为只读 JSON；若前端希望嵌入 SSR 页面，可复用同一服务端数据。
3. 证据“实际支持”当前采用数值等价/原文标记的文本校验；表格跨列脚注场景若需更强绑定，需扩展证据结构。
