## 模块与调用边界

| 模块 | 职责 |
|---|---|
| harness-plugin/src/tools.ts | 十工具唯一白名单、参数和描述，不给模型任务或路径参数 |
| harness-plugin/src/index.ts | 注册工具；新建或恢复 agent 时限制继承工具，全局 guard 拒绝原生工具 |
| harness-plugin/src/client.ts | 只请求回环原点，验证信封；宿主幂等键、取消与最多两次重试 |
| backend/src/esg_app/model_extractor.py | 后端检索证据、官方 HTTPS 模型请求、候选校验与用量 |
| backend/src/esg_app/agent_host.py | SDK 启动、绑定令牌、服务端审计校验和复核暂停 |
| backend/src/esg_app/harness_runner.py | 隔离路径、profile、patch、SDK 新建与恢复调用 |
| backend/src/esg_app/run_jobs.py | 运行状态、会话 ID 和同任务占用持久化 |
| scripts/prepare_harness.py | 安装构建到独立 profile，验证 JS 字节一致并生成单独 patch |
| scripts/run_task7.py | 预检、真实 PDF 运行、打开既有任务数据库供复核与继续 |

主智能体只选指标、年份和检查提案；后端负责提取、校验、版本、规则计算与存储。工具均走 /agent/tool，由令牌绑定任务。候选写入、SQL、人工确认、权重和文件输出路径不向主模型开放。

后端提取提示词与主智能体提示词分开维护。安装包镜像分别位于 esg_app/prompts；对应的两项一致性测试必须保持通过。SDK patch 的 persona 只设业务角色，不含用户输入或密钥。

```bash

  .venv/bin/python scripts/prepare_harness.py \
  --home data/harness/home --workspace data/harness/workspace

```

在本机配置文件填写 DEEPSEEK_API_KEY，核对 ESG_EXTRACTION_MODEL、DSH_MODEL、ESG_DSH_HOME、ESG_WORKSPACE、ESG_HARNESS_PATCH。不要发送密钥给其他人。data 已被忽略；本机现成配置为 data/integration-runtime/local.env，密钥为空，其他路径已准备。

home 与 workspace 必须独立。profile 安装是宿主操作，模型不能执行安装命令。不要随意调用 npm 类型包中的新方法：锁定 runtime 没有 presentAs；目前使用实装可用的作用域 restrict，并保留执行 guard。

## 真实首轮与复核后的继续

```bash
.venv/bin/python scripts/run_task7.py --env-file data/local.env \
  --pdf /绝对路径/比亚迪2024可持续发展报告.pdf \
  --company-id byd --company-name 比亚迪 --report-year 2024 \
  --years 2023 2024 --output data/task7/byd-run-001
```

输出目录必须不存在，避免覆盖旧证据。PDF 路径、元数据和 ID 均由可信宿主登记。脚本创建原件哈希、任务数据库及回环 HTTP 服务；SDK 与 HTTP 不在同一阻塞线程执行。run-summary.json 包含脱敏工具结果，answer.md 保留实际答复。

退出 0 可能是 waiting_review，不等于完整验收。完整分析缺少六指标年度覆盖、二十项检查或人工确认时会暂停。completed 还要求正常 SDK 回合、当前 get_task_results 的成功后端审计及当前版本导出；异常结束、截断、空答复或自然语言自称成功都不能替代这些条件。

暂停后，使用同一数据库和同一 SDK home 打开业务服务：

```bash
.venv/bin/python scripts/run_task7.py --env-file data/local.env \
  --serve --database data/task7/byd-run-001/task.sqlite3 --port 8000
```

访问 http://127.0.0.1:8000/。检查项复核走用户会话。继续运行走 POST /tasks/{task_id}/agent-runs，传 mode=resume 和最新 expected_revision；复用最近 waiting_review 的 session_id。用户问题始终作为任务数据嵌入，不直接当 SDK 命令路由输入。

当前指标人工确认入口仍需实现，必须有归属检查、expected_revision、修改理由、审计与相关结果失效；不要把 review_state 交给模型，也不要直接改库凑验收。该入口完成前，应如实停在复核阶段。

## 重试与异常恢复

模型不生成幂等键。插件根据宿主令牌、任务、工具及 session/call identity 生成 UUID，同一调用的客户端重试保持原键和原请求。仅明确瞬态错误最多重试两次；业务冲突先读最新结果，不再原样重试。

取消、超时和断连不证明远端回滚。新的宿主令牌不自动拥有旧调用的重放身份，恢复前先核对当前版本、后端提取占用和成功幂等结果。不要在客户端重试之外让模型再叠加相同重试。

SQLite 中 agent_runs 保存运行与 session_id，agent_run_claims 防止同任务并发启动，agent_tool_calls 保存令牌哈希和工具结果，extraction_attempts 保存调用占用及实际用量。worker 退出后 running 占用不会自动过期；确认执行与提交状态后再由可信宿主处理，不能直接删锁重跑。

SDK 正常结束后仍可能需要人工复核。后台状态和 SDK 对话是两类持久记录：前者重启恢复已测试，后者必须取得真实持久对话才能验收。
