# 三人协作约定

## 分工

- 队长/后端开发：需求、业务后端协调、指标提取模型/规则、提取提示词、校验计算评分、申报材料。
- 智能体成员：Python SDK宿主/Harness接入、10工具插件、主智能体编排、检查建议、追问解释及联调；不重复开发指标提取模型。
- 资料成员：公开报告、独立标注、证据/单位/年份核验、错误清单和验证。

后端接口交付的是可调用能力。不要等后端全部做完才联调：先固定contracts，插件用mock结果开发，后端逐项替换真实能力。

## 分支与PR

Codex统一复用codex分支开发并提交PR，不为每次修改新建分支；同源分支有开放PR时更新已有PR。其他成员可使用feat/backend-evidence、feat/harness-tools、data/byd-gold等分支。main保留可运行或明确标注的初始化状态。

PR前检查完整差异、受影响模块和必要测试；接口修改同步规范、Schema、示例、提示词和调用方。标题正文描述最终行为与实测结果，不把mock当真实接入。不覆盖用户或队友未提交修改。

## 第一轮目标

1. 后端：extract_metrics完成提取、校验、保存并返回证据；search_evidence支持原文核对。
2. 智能体：11/21前完成SDK→工具→HTTP→结果的真实闸门，之后读取任务→调用提取工具→校验/读取结果→回答。harness_runner.py由该成员维护，后端成员配合业务路由；不要阻塞HTTP服务。
3. 资料：核对比亚迪六指标和脚注，提交可追溯参考数据。

共同验收：用户问一项指标，智能体调用真实后端提取/缓存，返回数值、单位、年份、原文页码和未知项。

## 文件与目录

后端唯一代码位置为backend/src/esg_app/；根目录保留tests、rules、contracts。不要在根目录另建src/esg_app/。

不提交密钥、完整PDF、候选人材料、本地数据库及未脱敏日志。新成员由所有者邀请写权限；不共享账号或密钥。
